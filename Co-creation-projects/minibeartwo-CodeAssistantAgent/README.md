# CodeAssistantAgent · 本地代码助手

基于 HelloAgents 的桌面代码助手，通过蓝金主题客户端完成代码中文注释、项目解析、修改审阅和测试验证。项目目录遵循共创规范：`minibeartwo-CodeAssistantAgent`。

当前版本为可运行的 MVP：Electron 客户端会启动并管理本地 Python 服务。接入兼容模型后，可以在自己的项目中提问、审阅补丁、应用修改并查看实际测试结果。

![代码助手首页](docs/screenshots/home.png)

点击菲比桌面挂件打开此客户端，默认窗口为 650×500，界面整体以 65.625% 显示，最小可调整到 640×480，可拖入项目文件夹或代码文件。选择“代码注释”或“项目解析”后，在同一蓝色界面的任务面板中确认需求并开始处理；关闭面板后可点击“继续任务”恢复任务或草稿。原有 IDE 工作台界面及编辑器依赖已经移除。

[查看任务面板截图](docs/screenshots/client.png)。截图来自本地协议测试：修改经过实际审阅和应用，测试输出来自真实 pytest；模型端使用确定性的测试服务。

## 已实现的功能

- 菲比啾比桌面挂件：待机保留用户选定的 3D 人物图，悬停时双手背后、前倾歪头探看，点击时闭眼笑着小跳；单击展开或收起客户端，拖动调整位置，右键菜单提供“配置模型”和退出。
- 蓝金主题首页：项目拖入、代码中文注释、项目说明文档入口；无边框标题栏支持拖动、最小化、最大化和关闭。
- 项目导入反馈：成功后显示发光文件夹、确认勾选、“项目已就绪”和项目名称，播放一轮边框流光、扩散光环与蝴蝶星光；重复导入也会反馈，完成后保持清晰的静态就绪状态。点击或拖入可更换项目，取消或失败保留原项目，系统“减少动态效果”模式禁用动效。
- 清除项目：点击项目卡片右上角“×”恢复空的拖入框，重启后仍保持清空；保留本地文件和历史任务，再次导入可继续查看历史。任务或相关操作进行中时暂不可清除。
- 拖入本地项目或代码文件，在两个功能面板中配置需求、查看任务活动与结果。
- 项目解析：按目标项目的真实代码生成 `项目说明.md`、设计图说明及架构/流程/时序三张 PNG，校验后自动接受并应用，保留预览和撤销。仅静态阅读，不执行目标项目。
- HelloAgents LLM 流式适配与 ToolRegistry 工具调度；应用负责有预算的 Agent 循环。
- 生成补丁后暂停，在任务面板中按文件查看差异并接受或拒绝；接受后继续验证。
- 文件发生外部变化时保留当前内容，重新读取并生成补丁。
- 运行当前任务预先授权的 Python/npm 测试与构建，显示真实输出和退出码。
- 取消任务、停止命令进程树；累计调用次数与执行时间预算。
- SQLite 保存会话、任务、递增事件及补丁检查点；支持事件重连与补丁撤销。
- 模型设置页；API Key 优先存入系统凭据库，无法使用凭据库时保存在内存。

## 技术栈与架构

| 层次 | 实现 |
| --- | --- |
| 桌面外壳 | Electron，主进程管理窗口、目录选择与 Python 服务 |
| 交互界面 | React、TypeScript、Vite，统一蓝金主题首页和任务面板 |
| 本地服务 | Python 3.11+、FastAPI、Uvicorn、HTTP + SSE |
| Agent | HelloAgents 0.2.9 的 HelloAgentsLLM 与 ToolRegistry，自定义可恢复循环 |
| 工具与数据 | rg / Python 文本检索、Git、受限命令入口、SQLite、keyring |
| 设计图生成 | Pillow 本地绘制 PNG，模型只提交节点、连线和时序消息 |

客户端页面通过 Preload 暴露的固定接口调用主进程；主进程通过随机令牌连接 `127.0.0.1` 上的服务，令牌不暴露给页面。界面资源随应用构建，运行时不依赖在线编辑器资源。

## 快速开始

以下命令在本项目目录执行：

```powershell
cd "E:\hello agents\hello-agents\Co-creation-projects\minibeartwo-CodeAssistantAgent"
```

需要 Python 3.11+ 和 Node.js 22.12+。Windows 为当前验证平台；Git、rg 可选，缺少 rg 时使用有范围限制的 Python 文本检索。

首次安装：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -Dev
```

`-Dev` 安装 pytest 等测试依赖，方便运行示例。只使用问答与编辑时可省略；另加 `-Notebook` 可安装 JupyterLab。

启动：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

已经完成安装后，可以直接执行启动命令。启动后会在桌面右侧显示悬浮气泡，单击打开客户端，再次单击收起。关闭客户端窗口会回到气泡，会话、未保存的编辑和后台任务继续保留；右键气泡选择“退出代码助手”才会退出并停止本地 Python 服务。

气泡可以拖动，松开后记住位置；客户端展开时优先显示在菲比左上方，让菲比位于客户端右下侧并与窗口底部对齐；上方空间不足时会适当下移菲比。其他屏幕边缘按可用空间自动避让，保证窗口可见。展开采用约 480 毫秒的原地均匀渐显，收起采用约 180 毫秒的原地淡出；动画仅改变透明度，定位在显示前完成，避免逐帧移动原生窗口产生卡顿。连续点击可中途反向过渡，系统启用“减少动态效果”时直接切换。客户端展开时，拖动菲比会带着客户端一起移动，保留相对位置，贴近屏幕边缘时自动调整避免遮挡或移出屏幕；客户端收起时只移动菲比，下次展开使用新位置。手动最大化的窗口保留最大化状态。屏幕分辨率或显示器发生变化时，会自动调整到可见区域。重复启动会唤起已有客户端，不会再开一套后台服务。当前没有启用开机自启动。

待机沿用用户提供的 3D 菲比啾比原图。挂件按屏幕刷新节奏连续播放，使用相同落脚位置和头身关键点衔接姿态；点击的蓄力、腾空、落地与恢复由同一时间线控制，同时开始客户端的展开或收起过渡。快速移入、移出或连续点击会从当前画面接续；按压和拖动保持当前姿态，拖动抑制点击反馈。系统“减少动态效果”模式使用静态反馈。[查看贴图和制作说明](desktop/electron/assets/README.md)。

![桌面悬浮气泡](docs/screenshots/bubble.png)

开发时启动热更新：

```powershell
.\start.ps1 -Dev
```

## 模型配置

启动后右键菲比，选择“配置模型”直接打开设置界面，无需先导入项目；也可点击客户端右上角“模型设置”。填写：

顶部“配置列表”展示已保存的连接，选择后立即使用对应配置；“新建配置”打开独立的空白草稿，取消不会改变当前连接。可以填写配置名称，留空则自动命名。“保存连接”会保存并使用当前配置：编辑已有条目时更新原条目，新建时保留原有配置并新增一条。旧版单一配置会自动迁移为“默认配置”，列表和当前选择会在重启后恢复。“删除配置”移除所选已保存配置；删除当前配置时自动使用剩余的第一个配置，全部删除后回到空白表单。

1. API 地址：在服务商下拉框中选择 DeepSeek、Kimi 或“自定义服务商”。预设自动填写地址；自定义会弹出地址输入窗口，确认后应用，取消则保留原配置，之后可点击“编辑地址”修改。右侧“测试连接”可检查访问状态并查看耗时。
2. 模型名称：填好 API 地址和下方 API Key 后，点击“获取模型列表”从下拉框选择；也可以切换“手动填写”输入模型 ID。
3. API Key：云端服务需要；本机无鉴权服务可留空。
4. 单任务最大执行步数，新建配置默认 1000 步，可自定义任意正整数，没有固定最大值；已保存配置保留原有步数。所有任务不设执行时间上限，可随时手动停止。旧配置中的执行时间上限自动移除。

内置地址按 [DeepSeek 官方文档](https://api-docs.deepseek.com/) 和 [Kimi 官方文档](https://platform.kimi.com/docs/api/overview) 配置。切换地址会清除原模型选择和未保存密钥，保存不同服务商的配置时不会沿用上一家的密钥；已有自定义地址会在重新打开配置时恢复。

获取列表使用当前尚未保存的配置，不会自动保存或启动任务；密钥留空时仅复用所选配置中相同地址的密钥，新建草稿不会借用其他配置的密钥。支持兼容的模型列表接口，服务不支持、返回空列表或获取失败时可继续手动填写。选择后点击“保存连接”生效。

“测试连接”同样使用当前表单配置，通过模型列表接口检查服务访问和鉴权，不发起模型生成。检测不受模型名称必填项限制；服务不支持检测时显示未验证提示，修改地址或密钥后清除旧结果。

当前使用 Chat Completions 原生工具调用：通过 `tools` 定义 `submit_action`，并用 `tool_choice` 指定该工具。客户端只解析 `delta.tool_calls` 的参数，正文与模拟结果分开处理；真实调用 ID 随任务历史保存，真实观察以 `role=tool` 回传。官方 DeepSeek 地址禁用思考模式，避免思考通道与工具协议混用。模型服务需要支持原生工具调用，连接测试成功不能代替协议兼容检查。`finish_reason=length` 会被识别为截断，未完成的动作不会执行，下一轮提示改用局部补丁；尚未对所有服务商做兼容验证。

已有文件可通过 `propose_patch.changes[].edits` 提交 `old/new` 精确替换，减少生成完整文件导致的输出截断。替换以同一次真实读取的 hash 为基准，原文必须唯一匹配且范围不重叠；后端在内存中拼出完整候选，保留注释静态校验、Diff 记录和应用后撤销。注释任务每个候选文件仍需覆盖完整文件头及全部具名函数，通过校验后自动应用并继续处理；项目解析文档包也在校验后自动应用，普通任务仍需审阅确认。

Python 注释补丁可以恢复确定的 CRLF/LF 差异，以及注释行丢失的统一缩进；附带的函数签名、装饰器与其他代码仍须逐字匹配，多个候选位置或文字差异不会进行模糊替换。恢复后仍经过完整静态检查。匹配失败会标明文件和 `edits[i]`，并把失败文件当前真实原文与 hash 返回给模型。漏填路径仅在本任务真实读取记录中 hash 唯一且文件仍未变化时补回；路径有歧义时拒绝写入。重复提交无变化的 Python 文件，只有注释覆盖检查通过才返回 `unchanged` 并继续，不产生空补丁；未完成注释的文件仍报告校验错误。

Python 文件头校验只统计真实注释，允许五项文件头位于原模块文档字符串之前或之后、首条代码或装饰器之前；shebang 保留首行，编码声明保留合法位置。读取源码时会一并向模型返回当前文件的合法头部位置、已检测字段和必需字段，错误反馈也包含检测值与修正位置。补丁参数通过工具 schema 描述并在本地校验，缺少 `changes[i].path` 或 `base_hash` 时明确提示字段，不再只显示裸 KeyError。

原生工具调用在非严格模式下仍可能生成不完整参数。客户端自动补齐“所有内部参数和字符串已完整、仅缺一个根对象结束大括号”的响应，或忽略完整对象之后多余的单个 `}`，并将误放在 `args` 内的进度说明归位；不猜测缺失代码、字符串、逗号或嵌套结构。回传给模型的原生工具参数也按恢复后的对象规范化，保留实际调用 ID。恢复仅影响参数封装，修改仍须通过参数与补丁校验。读取 Python 文件时还会提供各函数与装饰器的注释插入位置和参数清单，避免把多个函数的说明堆在同一个函数之前。

对于仍返回动作文本的兼容网关，允许读取类动作（list/read/search/git_diff/inventory）后的多余文本，但只执行首个读取动作，附带的模拟结果及后续动作全部丢弃。修改、测试及结束动作仍拒绝未知附加内容；DSML 不会被当成可执行代码。项目解析另支持真实原生工具响应中的只读批次，文本中的多个动作不当作批次执行。连续 3 次无有效动作时停止并提示原因，不通过放宽写入校验来兼容模型格式。

代码注释任务的模型请求超时会自动重试同一轮请求，等待间隔为 2、4、8、16 秒，之后每 30 秒重试，不限制重试次数。等待与超时重试不额外消耗执行步数；进度列表显示重试状态，可随时点击“停止当前任务”。未收到完整响应前不会执行工具或应用补丁。鉴权、参数和动作格式错误仍按原规则处理。代码注释与项目解析均无任务总时限；单次网络请求与测试命令仍有各自的超时机制。

也可以复制 `.env.example` 为 `.env`，填写 `LLM_MODEL_ID`、`LLM_BASE_URL`、`LLM_API_KEY`。已保存的界面配置优先于环境中的模型名称和地址。密钥不会返回给界面或写入 SQLite；本地模型连接会绕过系统代理。

每套连接的密钥分别存入系统凭据库；环境不支持凭据库时仅在本次服务会话内保留，界面会显示提示，重启后需补填密钥。切换连接不会把一套配置的密钥带给另一套。

## 使用示例

模型请求显式设置 `parallel_tool_calls:false`，优先每轮一个动作。项目解析兼容仍返回多个原生调用的服务：2–16 个调用全部为读取、目录、清单、搜索或 Git 差异时，先完整校验整个批次，再依次执行，并按真实调用 ID 逐项回传结果；模型请求计一步。源码按共享容量完整分页，读取失败的条目单独返回错误，其他读取结果仍保留。包含修改、文档提交、测试、结束动作或无效调用的批次会整轮拦截，文档包单独校验后自动应用，不与读取混合执行。`list` 根目录支持空字符串、`.`、`./` 和 `.\`；文件读取和写入仍要求具体的工作区相对路径。

只读任务可以输入：

> 介绍这个项目的入口和主要模块，并指出相关文件。

> 解释当前文件的职责，找出可能遗漏的边界情况。

注释流程可使用内置的 [buggy-calculator 示例](examples/buggy-calculator/README.md)：

1. 在客户端导入 `examples/buggy-calculator` 文件夹或其 `calculator.py` 文件。
2. 点击“代码注释”，面板会绑定 `annotate-project-zh`。可补充需求，处理范围始终是导入的整个项目；拖入单文件时，使用其所属项目文件夹。
3. 配置模型后点击“开始注释”。后端在每轮调用中保留完整技能规则：五项文件头、逐函数三项注释、全部参数说明、术语解释和真实文件路径，不修复或重构代码，也不新增说明文档。
4. 注释补丁校验通过后默认自动同意并应用，助手连续处理其余文件，无需逐文件确认。面板保留按文件展示的 Diff 与撤销记录。Python 补丁会在内存中比较 AST 和原始代码词法，并用技能附带检查器验证函数注释格式与参数覆盖，不导入或执行目标项目；其他语言不保证具备同等语义静态检查。写入前重新检查文件 hash，外部修改不会被旧补丁覆盖。
5. 在任务活动与结果中查看进度，可随时停止当前任务；结束或取消后可撤销补丁，“历史任务”可重新查看记录。升级重启时，旧版本处于“等待审阅”的注释补丁也会重新校验、自动应用并继续；已取消或中断的任务不自动恢复。预算或单文件大小限制导致未完成时，应按结果提示继续处理，不能将局部修改视为全项目完成。

展开“任务记录”后，每行右侧的“×”可删除该任务及其进度、Diff 和撤销记录，重启后也不会重新出现。删除当前记录会回到新任务；删除其他记录保留当前选择。已经应用到项目的文件不会因此回滚。执行中或等待审阅的任务需先停止；尚有补丁待恢复时需先恢复或撤销，再删除记录。

项目解析流程：

解析任务固定保留真实读取范围、源码摘录、顶层定义与导入关系。`read` 始终返回所请求文件，已读范围返回摘要，不替换成其他文件。长文件按完整行继续分页。`read.force:true` 可核对原文；连续两轮读取没有产生新依据时，由独立的客户端材料计划补齐其余候选文件。无法读取的文件单独记录为未覆盖范围。

只读批次按完整 JSON（含调用 ID、结果外层与状态字段）共享 18000 字符。读取结果通过最终容量校验后才保留进度，拒绝结果会回滚本轮读取覆盖记录。某个完整源码行无法放入共享页时，客户端在下一次模型请求前自动单独读取，不额外消耗模型步数；进度分别显示成功、待单独读取和失败项。

客户端负责阶段切换，所有阶段的原生工具名保持 `submit_action`。资料齐备后，参数只允许 `action: propose_documentation` 及项目说明与三图数据；校验并自动应用后，只允许 `action: final`，不会重新开放自由读取。原生调用 ID 和真实应用结果沿历史回传，兼容流式元信息的重复与累积发送。名称不匹配、ID 缺失会分别记录不含密钥和参数正文的诊断，不再统称为文档 JSON 错误。没有执行项目或测试时不会据此宣称已经验证其运行结果。

模型仅提交说明正文 `overview` 和图结构 `diagrams`。交付文件的版本由客户端在模型请求前固定，生成文档包和自动写入时分别检查冲突；模型不再填写文件版本。旧响应中位于参数或图容器内的 `base_hashes` 仅作为废弃元数据丢弃，不能覆盖客户端的真实版本记录。字段错误会指出具体 JSON 路径。

1. 导入项目后点击“项目解析”，补充说明需求并开始解析。新任务绑定内置 `analyze-project-zh` 规则，始终覆盖整个导入项目，不执行项目、测试或构建。
2. 助手先阅读文件清单、入口、依赖及关键实现，再按参考 README 的组织方式编写概述、功能、技术栈、目录与模块职责、安装配置、使用方法和当前边界。没有代码依据的信息应注明待核对。
3. 文档包校验通过后默认接受并自动写入以下五个文件，无需点击确认。面板保留两份 Markdown 的 Diff 与三张 PNG 的修改前后预览，支持整体撤销。生成期间或写入前发现版本冲突会停止任务，保留外部修改，不会自动刷新基线后覆盖：

```text
项目说明.md
docs/diagrams/README.md
docs/diagrams/architecture.png
docs/diagrams/workflow.png
docs/diagrams/sequence.png
```

`项目说明.md` 链接设计图和图说明；图内容反映目标项目本身，不照搬本项目的技术栈或功能。源代码和原有 `README.md` 保持原样。图由本地 Pillow 绘制，因此无需模型具备生图能力；Windows 默认使用系统中文字体，其他平台需安装 Noto Sans CJK 等中文字体，也可通过 `CODE_ASSISTANT_FONT_PATH` 指定字体文件。重新生成时，已有同名交付文件也会在版本校验通过后自动更新，并保留撤销备份。

代码注释任务因取消、服务重启、模型报错或步数用尽而中断时，可在该任务的“处理进度”中点击“继续执行”。继续使用原任务的需求、技能快照、历史和已应用补丁，不清零执行步数；模型使用点击时的配置，因此可在充值或更换模型连接后重试。达到步数上限时须先在模型设置中提高步数；已完成、已删除及项目解析任务不提供续跑。继续后会重新核对当前文件，已应用补丁不自动重放。

注释任务在 SQLite 独立保存完整文件清单、真实读取范围、文件 hash 和已验证/已应用/受阻状态，每轮固定提供待办摘要，历史裁剪不会丢掉进度。开始时建立清单缓存，分页不会重新遍历项目，结束前再次核对清单与完成文件的当前 hash。已有完整格式的 Python 文件首次仍返回真实源码供核对，读完整后才允许以简短说明代替重复读取；本任务已应用且 hash 匹配的文件可直接返回简短记录。需要重新核对原文时可使用 `read.force:true`。续跑会核对完成文件的当前 hash，外部编辑、撤销或文件新增会重新进入处理范围；已应用旧补丁仅在当前文件 hash 仍匹配时用于恢复进度。

超过 24000 字符的 Python 文件使用分函数注释流程：客户端确定文件头与全部具名函数的顺序，每轮只向模型提供一个单元的真实源码或明确标注的模块概览，原生工具只允许提交该单元的中文注释字段。模型不再通过自由 `read` 反复拼凑整篇文件。客户端负责缩进、换行、注释位置和汇总，草稿逐项保存到 SQLite；全部单元完成后仍执行完整文件 AST、词法、文件头及函数覆盖检查，然后只应用一个文件补丁并保留 Diff/撤销。草稿保存本身不代表文件已写入，进度会显示“已保存…注释草稿（已完成/总数）”。

停止、预算用尽或服务重启后，“继续执行”会复用同任务已经保存的草稿，从下一个未完成单元继续；文件 hash 变化会使旧草稿失效，已应用或已撤销的草稿不会直接重放。单元格式校验失败会针对当前单元反馈，连续三次失败暂停并保留已完成草稿；网络超时仍重试同一单元，鉴权与余额错误直接报告失败。单个函数的完整序列化材料超过 22000 字符，或汇总候选不能通过安全校验时，会明确记录受阻文件并继续其他范围；不会截断函数后假称已经处理完成。

通用读取仍支持 `read.start_line/end_line` 分段，返回真实行范围、完整文件 hash、`next_start_line` 和是否读完；每页按 JSON 转义后的体积限制，保留原始换行。超过 256 KB、非 UTF-8、二进制或无法安全分页的超长单行会明确记录受阻原因。

运行器直接识别注释工具的真实错误并返回结构化恢复说明。没有新增文件读取范围、文件版本变化、真实搜索/目录证据或注释写入时，同一动作重复 3 次或累计 6 步无进展会提示纠偏；同一动作重复 6 次或累计 12 步无进展会暂停任务，保存现场并显示“继续执行”，不会持续消耗到总步数上限。新文件、新分页和真实修改会重置本轮检测；重叠页、相同搜索结果及虚构缺失路径不算新进展。网络超时等待沿用无限重试，不算工具死循环。结束结果附带客户端实际进度和受阻范围，格式检查通过不等于注释语义质量已经验证。

这个示例故意包含计算错误，注释流程会保留原有行为。注释内容质量取决于所连接的模型；静态格式检查不能替代对注释含义的人工核对。

技能完整保存在 [`skills/annotate-project-zh`](skills/annotate-project-zh/SKILL.md)，源自用户提供的同名 Codex 技能，不依赖开发电脑的绝对安装路径。创建任务时会保存技能规则快照，后续审阅、历史与重启使用同一任务规则；仅对新任务应用后续技能文件更新。

历史通用任务的测试入口支持 `python -m pytest/unittest/compileall`、`pytest` 和 `npm test` / `npm run test/build/lint/typecheck`。命令按空白拆分，当前不支持带空格的引号参数。Python 测试使用后端解释器，需要在该环境安装目标项目的测试依赖。当前两个功能按钮创建的注释和项目解析任务均只做静态处理，不使用测试入口。

## 当前边界与后续计划

- 常规工具仅处理 UTF-8 文本；文件读取上限 256 KB，每批补丁最多 5 个文件。普通任务与完整文件重写限制为单文件 24000 字符；较大 Python 文件自动分函数生成草稿，单元材料最多 22000 字符，候选仍须小于 256 KB 并通过完整静态检查。项目解析的固定交付通道另支持本地生成的静态 PNG（每张最多 256 KB），已有图的撤销备份上限为每张 8 MiB。单函数过大或候选受阻会明确报告未覆盖范围；其他语言仍使用受限工具流程。检索范围最多 800 个文件、60 条结果，注释与解析清单不受 800 文件限制，暂未提供向量索引。
- 文件工具屏蔽常见密钥、数据库和依赖目录，校验解析后的路径。命令入口只接受列出的测试/构建类型；项目测试本身会执行本地代码，因此当前不提供操作系统级沙箱。
- 应用/撤销使用逐文件原子替换与持久化检查点；跨多个文件的操作无法保证断电原子性。重启后“需要恢复”的补丁可在结束任务后撤销，外部修改发生冲突时不会覆盖。
- 执行中的任务在服务重启后标记中断；仅等待审阅的注释补丁会重新校验并自动应用、继续注释，其他待审阅补丁保留确认流程。不会自动重跑中断的命令。
- 本地取消会停止调度和命令进程树；已发给远端的模型请求能否停止计费由服务商决定。
- 尚未实现自动补全、完整 LSP、Skills/MCP、Git worktree 隔离及安装包发布。后续可按已确认架构扩展。
